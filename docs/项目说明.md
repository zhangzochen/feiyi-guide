# 见物 · 知艺：项目说明

## 一、项目定位

“见物 · 知艺”是一个面向非遗展馆场景的 AI 讲解员。观众不用读完一整面展板，也不用等讲解员有空，而是可以直接问一件展品：它从哪里来、怎么做、为什么好看、今天怎么看。

项目不是做一个“什么都能聊”的聊天机器人，而是把 9 件非遗展品拆成一套小型知识库，让回答有依据、有来源、有边界。

## 二、项目目标

1. 让观众用自然语言了解展品的历史、工艺、纹样、产地和参观方式。
2. 让回答可以追溯：每条回答下方标注知识来源，方便回到原文核对。
3. 让找不到答案的时候不编造：明确说“不确定”，并建议现场咨询。
4. 让讲解可以听：调用浏览器中文语音，把展品介绍和回答朗读出来。
5. 让系统可以低成本运行：不配置大模型 Key 也能演示，配置后自动升级为真实 embedding + 大模型。

## 三、预期效果

产品成果：
- 一个可直接访问的 Web 应用，地址为 http://localhost:8081
- 9 件非遗展品、16 篇讲解词、54 个知识片段
- 展品详情、语音讲解、AI 对话、来源引用、移动端适配
- 一个可运行的后端 jar 和一套可继续扩展的源码

技术指标：
- 问题命中知识库时，返回 1—4 条来源
- 领域外问题不编造，明确提示超出讲解范围
- 展品关键词自动路由，例如“苏绣”“青花”“龙井”
- 无 API Key 时仍可完整演示；有 Key 时可切换真实生成

社会效益：
- 降低小展馆、校园非遗展、线上展馆的讲解人力压力
- 让非遗从“被看见”走向“被听懂、被记住”
- 为不会写讲解词的基层展馆提供可复用的知识库模板

## 四、技术方案

后端：
- Java 17 + Spring Boot 3.5
- Spring Data JPA + H2（默认演示库，可切换 MySQL）
- REST API：展品、类别、问答、知识库管理

RAG 流程：
1. 讲解词按段落切块，写入 kb_chunks
2. 有 API Key 时调用 /embeddings；没有时使用本地字符 + 二元组哈希向量
3. 用户提问后，先做展品关键词路由，再做混合检索：向量余弦相似度 + 关键词重合度
4. 取 Top-K 片段拼接上下文
5. 有 Key 时调用 /chat/completions 生成；没有时使用抽取式回答
6. 返回答案、置信度、是否建议人工、来源列表

前端：
- 原生 HTML/CSS/JS，无框架、无 CDN 依赖
- 宣纸底色、宋体标题、朱砂红与墨色
- 展品卡片、详情弹层、聊天抽屉、语音朗读、移动端适配
- 支持 #detail-1、#chat 深链接，方便演示

## 四、DeepSeek 真实接口验证

项目已使用 DeepSeek 官方 API 完成真实问答验证：

- Base URL：https://api.deepseek.com
- 模型：deepseek-chat
- 验证问题：青花瓷的蓝色从哪里来？
- 返回标记：engine=deepseek
- 回答内容由 DeepSeek 结合本地 RAG 资料生成，并保留两条知识来源

DeepSeek 目前没有公开 embedding 接口，因此检索仍使用本地哈希向量 + 关键词重合度，DeepSeek 负责最终讲解生成。API Key 只保存在本机启动器配置中，不写入项目源码。

## 五、创新点

1. 一展品一知识库：不是全站一个大知识库，而是每件展品有自己的讲解词和来源。
2. 混合检索：向量相似度 + 关键词重合度，专有名词和工艺细节更稳。
3. 展品路由：问“苏绣”“青花”“龙井”时自动定位到对应展品。
4. 答案可追溯：每条回答都能点回来源，避免“听起来对但没有依据”。
5. 有边界的讲解：不知道就说不知道，不把大模型的自由发挥伪装成展馆官方说法。

## 六、3 分钟演示脚本

1. 打开首页，介绍“9 件展品、16 篇讲解词、54 个知识片段”。
2. 点开“景德镇手工制瓷”，点“听讲解”，展示语音朗读。
3. 在对话框问：“青花瓷的蓝色从哪里来？”
4. 指出回答下方的来源：“景德镇：一件瓷器的七十二道工序”。
5. 再问：“苏绣的双面绣难在哪里？”展示自动切换到苏绣知识库。
6. 问：“你们老板是谁？”展示领域外问题不编造。
7. 最后总结：知识库 -> 混合检索 -> 生成 -> 来源追溯。
